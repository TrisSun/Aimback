# 短信接入文档（阿里云 PNVS · 失物招领平台）

> 本文记录 B 子任务里短信验证码从零接入到上线的全部步骤，供后续开发者（含下一轮 B、未来答辩演示者）按图索骥，**不需要重新踩坑**。
>
> **技术决策**：阿里云 PNVS（号码认证服务 / One-Number Authentication）— 由 `docs/技术路径大纲01.md` 指定。

## 一、整体设计

短信模块位于 `backend/apps/accounts/sms.py`，对外暴露两个端点（`backend/apps/accounts/views.py`）：

| 端点 | 方法 | 作用 |
| --- | --- | --- |
| `/api/v1/auth/send-code/` | POST | 给指定手机号发验证码 |
| `/api/v1/auth/login-code/` | POST | 用户用验证码登录（新手机号自动注册） |

### 1.1 通道设计（多通道 + 主备）

`sms.py` 支持四种通道，**`.env` 里 PNVS 四项都填齐 → 自动走 PNVS；任一空 → 落回 console（dev 模式）**：

| 优先级 | 通道 | 说明 |
| --- | --- | --- |
| ① | **pnvs** | 阿里云号码认证服务（**默认**，大纲指定）。免签名免模板，个人实名即可 |
| ② | dysms | 阿里云普通短信（备选），需自申请签名 + 模板 |
| ③ | tencent | 腾讯云短信（备选），预留扩展位 |
| ④ | **console** | 开发模式，**不发真短信**，验证码在响应 `dev_code` 字段返回 |

### 1.2 校验设计（混合：PNVS 发 + 本地验）

- **发送**：调用 `SendSmsVerifyCode` 并设 `return_verify_code=True`，阿里云会**把生成的验证码回写到我们的后端**
- **校验**：不调 `CheckSmsVerifyCode`（这个接口在我们账号上持续 `isv.ValidateFail`，工单提了也没解），而是把拿回的码存进 **Django 本地 cache**（5 分钟 TTL，一次性消费）

> 单进程开发：`locmem` cache 即可；**生产环境必须切 Redis cache**，否则验证码跨进程不一致。

## 二、必填的环境变量

四个变量填齐即真短信生效（`.env` 模板见 `backend/.env.example`）：

```ini
ALIYUN_PNVS_ACCESS_KEY_ID=...        # 阿里云 AK ID
ALIYUN_PNVS_ACCESS_KEY_SECRET=...    # 阿里云 AK Secret
ALIYUN_PNVS_SIGN_NAME=...            # 短信签名（控制台签名列表）
ALIYUN_PNVS_TEMPLATE_CODE=...        # 模板 CODE
```

`SIGN_NAME` 和 `TEMPLATE_CODE` 的特殊之处：

| 变量 | 来源 | 备注 |
| --- | --- | --- |
| `SIGN_NAME` | 不是 `签名名称`，而是**签名 API 串** | 例：`恒创联众`（阿里云网页里那个显示的名字） |
| `TEMPLATE_CODE` | 不是模板内容，是**模板 ID** | 例：`100001`（即 `PVN-XXXX` 类的代号） |

> ⚠️ **模板内容固定为 `${code}`**，传参时必须带 `{"code": "##code##", "min": "5"}`，PNVS 会把 `##code##` 替换成系统生成的 6 位码，把 `min` 当发送间隔。

## 三、完整配置流程

### 3.1 控制台准备

1. 登录阿里云 → 访问[号码认证服务控制台](https://dypns.console.aliyun.com/)
2. 首次进入会要求**实名认证**（个人 / 企业均可，个人免费额度够用）
3. 不需要买套餐包就能测（按量计费，约 0.045 元/条）

### 3.2 创建 RAM 子账号

不能用主账号 AK，直接建子账号更安全：

1. 访问 [RAM 访问控制](https://ram.console.aliyun.com/) → 用户 → 创建用户
2. 登录名称自定义（如 `sms-dev`），**访问方式勾选 "OpenAPI 调用访问"**
3. 创建成功后弹窗里**复制 AK ID 和 AK Secret**（Secret 只显示一次，关了就没了）
4. 给用户授权：**AliyunDypnsFullAccess**（号码认证服务完整权限）

> 老的 AK 不用时记得在 RAM 控制台**禁用**，避免被滥用扣费。

### 3.3 创建签名和模板（如果用 dysms 才需要）

PNVS 走的是**认证类型 + 系统模板**，**不需要自建签名和模板**。如果你后续切到 `dysms` 普通短信通道，则需要在 [短信服务控制台](https://dysms.console.aliyun.com/) 分别创建：

- 签名：例 `恒创联众`（签名需要 ICP 备案 / 资质，**个人开发者很难批**）
- 模板：内容固定 `您的验证码为：${code}，5 分钟内有效`

> 这也是为什么默认走 PNVS 的原因之一。

### 3.4 写 `.env`

复制 `backend/.env.example` 到 `backend/.env`：

```bash
cd backend
cp .env.example .env
```

然后填入四个 PNVS 变量值。

### 3.5 验证

启动服务：

```bash
cd backend
python manage.py runserver
```

发验证码（dev 模式会返回 dev_code；真短信模式只返回 `{"ok": true}`）：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/auth/send-code/ \
  -H "Content-Type: application/json" \
  -d '{"phone": "13800000001"}'
```

真短信成功会收到手机验证码；登录验证：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/auth/login-code/ \
  -H "Content-Type: application/json" \
  -d '{"phone": "13800000001", "code": "你收到的6位数"}'
```

成功响应里有 `token` 字段，保存起来就是登录态。

## 四、故障排查速查表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `TemplateParam is mandatory` | 没传 `{"code":"##code##", "min":"5"}` | 看 `sms.py` 里 `SendSmsVerifyCode` 的 `TemplateParam` 参数，必须两个 key 都带 |
| `InternalError: System Internal Error` | `TemplateParam` 格式不对（字段顺序 / 引号 / 多了空格） | 严格按 `{"code":"##code##","min":"5"}` 字符串写，紧凑无空格 |
| `isv.ValidateFail`（来自 CheckSmsVerifyCode 校验） | PNVS 校验接口在我们账号上有 bug | **改用本地 cache 校验**，见 1.2 节 |
| `Content (Signature) does not match` | RAM 用户没授权 | RAM 控制台 → 用户 → 授权 `AliyunDypnsFullAccess` |
| 一直走 dev 模式（返回 `dev_code`） | 四个 PNVS 变量有任意一个没填 | 检查 `.env` 是否有空字符串 / 多空格 |
| 间歇性 502 | 跨服务网络抖动 | 重试一次 |
| 收到短信但 login 报 "验证码错误" | 用了别的设备 / 隔太久（>5 分钟） | 重发验证码，立刻用 |
| `SignatureNonce` 错误 | AK Secret 重置过但服务端没刷新 | 重启 Django 进程 |

## 五、安全与上线 Checklist

上线前逐项核对：

- [ ] `.env` 不进 git 仓库（`.gitignore` 必加 `.env`）
- [ ] AK 用的是 RAM 子账号，权限最小化为 `AliyunDypnsFullAccess`，不要用主账号 AK
- [ ] 老的测试 AK 在 RAM 控制台**禁用**
- [ ] cache 后端从 `locmem` 切到 **Redis**（多进程 / 多机部署）
- [ ] `/auth/send-code/` 已经有 IP + per-phone 限流（DRF throttle，详见 throttle 测试脚本）
- [ ] `/auth/login-code/` 已经有 IP 限流
- [ ] 给前端发验证码时 **dev_code 字段必须在 dev 模式禁用**（生产环境从配置读）
