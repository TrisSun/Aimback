## 2. 这台机器上跑什么、不跑什么

大纲已定：服务器只跑业务，**不跑模型**。图片在 COS，AI、地图、短信都走云 API。

| 跑 | 不跑 |
| --- | --- |
| Nginx（HTTPS、静态网页、反代 API） | 任何本地 Embedding / 大模型 |
| Django API **1 个进程** | 图片原图长期落本地盘 |
| Worker **1 个进程**（向量化任务、后续审核） | PostgreSQL / Redis 公网端口 |
| PostgreSQL + pgvector | 多 worker、多 gunicorn 进程 |
| Redis（队列、缓存、验证码频控） | Kubernetes / Elasticsearch |

内存预算（4 GB 必须按这个量级，打满就 OOM）：

| 用途 | 预算 |
| --- | --- |
| 系统预留 | 约 0.5 GB |
| PostgreSQL | 约 1.5 GB |
| Redis | 约 0.3 GB |
| Django + Worker | 约 1.2 GB |
| 突发余量 | 其余 |

60 GB 磁盘留给系统、数据库、日志和备份缓存；日志按天轮转。原图进腾讯云 COS 私有桶，不进这台盘。

## 3. 登录与控制台

控制台提供三种登录，任选其一即可：

1. **免密登录**（OrcaTerm 网页终端）
2. **密码 / SSH 密钥登录**（本地 `ssh ubuntu@118.25.145.183`）
3. **VNC 登录**（网页图形终端，应急用）

建议全组统一用 SSH 公钥，不要把登录密码写进仓库或群公告。密钥文件只放本机，需要给别人时走私聊。

首次登录建议确认：

```bash
whoami          # 应为 ubuntu
lsb_release -a  # 记下 Ubuntu 版本，补进本文「系统」一行
free -h
df -h
```

把 `lsb_release -a` 的具体版本（例如 Ubuntu 22.04 / 24.04）发群里，由文档维护人补全第 1 节。截图只能确认是 Ubuntu，写不准次版本。

## 4. 网络与安全

- 轻量自带防火墙。公网只开放 **22（SSH）、80、443**。不要开放 5432（Postgres）、6379（Redis）、8000（Django 开发端口）。
- PostgreSQL 与 Redis 只监听 Docker 内网或 `127.0.0.1`。
- 域名解析、HTTPS 证书由 B 在第 5 天部署阶段处理。ICP 备案通过前，**不要**用备案域名对外提供网站服务；可用 IP + 自签或先内网联调。
- 云 API 密钥（百炼、COS、短信）只进服务器上的 `.env` 或 Compose 环境变量，**禁止**写入 Git。仓库是 Public。

流量包按月计，图片走 COS 不经这台机中转，正常联调耗不完 800 GB。仍避免在服务器上 wget 大文件、反复拉镜像不清理。

## 5. 软件与目录约定（待 B 落地）

目标形态用 Docker Compose，服务清单见《技术路径大纲01》第 9 节。建议主机目录（B 可改，改了写回本文）：

```text
/opt/aimback/           # 仓库检出或发布目录
/opt/aimback/.env       # 生产密钥，chmod 600，不进 git
/var/lib/aimback/pg     # Postgres 数据（或 Compose volume）
/var/log/aimback/       # 应用与 Nginx 日志
```

主机侧建议具备：`git`、`docker`、`docker compose`、`ufw` 或轻量防火墙。Python / Node 跑在容器里，**不要**在宿主机再装一套和容器抢内存的运行时，除非临时排障。

时区：应用层已约定 UTC（见接口契约）。操作系统时区用 UTC 或 `Asia/Shanghai` 均可，但 Nginx / 日志与 Django `TIME_ZONE = "UTC"` 不要混用后还按本地时间对日志。

| 阶段 | 谁 | 做什么 |

| 第 5 天 | B | Compose、Nginx、HTTPS、Postgres + pgvector 初始化 |

E 的向量化调用阿里云百炼，**不占用这台机的 GPU/CPU 跑模型**；Worker 只负责调 API、写库。最小 demo 可以在这台机上跑（只是一次 HTTP 调用，内存可忽略），步骤见下文第 9 节。不要在这台机上装本地大模型或反复 `docker pull` 占满磁盘。

## 7. 备份与容量

- 数据库每日备份到 COS，保留 7 天；只备份不恢复演练等于没有备份。
- 系统盘 60 GB：系统约已用 6 GB，剩下主要给 Postgres 数据、镜像层和日志。镜像用完及时 `docker image prune`。
- 套餐到期日 2027-08-12，答辩周期内无需续费；仍打开到期提醒，避免实例释放导致数据丢失。

## 9. 在本机跑百炼 Embedding demo（E）

这只是一次云 API 调用，不在服务器上跑模型。2 核 4G 完全扛得住。密钥只写服务器上的 `.env`，不要 `git add`。

```bash
# 1. 登录（网页免密或本地 SSH）
ssh ubuntu@118.25.145.183

# 2. 系统包（若已有 python3/venv/git 可跳过）
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git

# 3. 检出仓库（已有目录则 git pull）
mkdir -p /opt/aimback
cd /opt/aimback
# 还没有仓库时：git clone https://github.com/TrisSun/Aimback.git .
# 个人分支：git fetch && git checkout dev-e && git merge origin/main

# 4. 独立小 venv，不要在宿主机装全套 Django
cd /opt/aimback/backend
python3 -m venv .venv
source .venv/bin/activate
pip install dashscope python-dotenv

# 5. 写入 Key（nano 粘贴后保存；文件已被 gitignore）
cp -n .env.example .env
nano .env
# 填：DASHSCOPE_API_KEY=sk-你的北京Key
# 若默认空间调不通，再填 DASHSCOPE_WORKSPACE_ID=控制台业务空间ID
chmod 600 .env

# 6. 跑三条用例：文+图融合 / 仅文字 / 多视图
python scripts/embed_demo.py
```

成功应看到三次 `status_code=200`，`type=fused` 或文本类型，`dim=512`，最后一行「全部通过」。

`InvalidApiKey`：Key 不是北京的，或粘贴带了空格换行。找不到模型：补 `DASHSCOPE_WORKSPACE_ID`。
